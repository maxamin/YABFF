# Fingerprint classifier benchmark

Head-to-head comparison of candidate classifiers for the framework
fingerprinter, on the `ferox-ml-core` 24-dim feature space. Generated by
[`scripts/classifier_benchmark.py`](../../scripts/classifier_benchmark.py).

**Method.** Centroids, weights and feature names are parsed from
[`profiles.rs`](../../ferox-ml-core/src/profiles.rs). A labelled dataset is
sampled per profile as Bernoulli(centroid-probability), then corrupted with
**15% bit-flip observation noise** (flaky probes / catch-alls) —
1470 train / 630 test, stratified 70/30 over the 7 profiles.
Metrics are macro-averaged on the held-out test set. The companion heatmap is
[`fingerprint-classifier-heatmap.html`](fingerprint-classifier-heatmap.html).

> **Caveat — synthetic data.** This measures how well each algorithm
> *separates the profiles under observation noise*, not real-world yield. The
> product-of-Bernoullis generator mildly favours Naive Bayes (its assumption
> matches). The real unlock is a labelled corpus of actual hosts; treat this
> as an algorithm comparison that motivates the choice.

## Reading it

- **Best at 15% noise:** Bernoulli Naive Bayes (acc 0.808, F1 0.808).
- **Shipped baseline** (hand centroids, *no training data at all*): acc 0.783, F1 0.782 — within 0.025 of the best trained model.
- The sweep shows the ranking is **stable across noise**; the gap to the best
  trained model widens only as noise grows, and every model needs a labelled
  corpus to train — which the hand centroids do not.
- Near-origin profiles (SPA / DJANGO / PHP / STATIC) are the dominant
  confusions — see the per-classifier matrices in the heatmap.

## Recommendation

The algorithm is **not** the bottleneck on this feature space — all candidates
cluster tightly and the zero-data hand centroids are competitive. The real
levers, in order: **(1) richer features** (response-body / header / favicon /
JS-framework signals), **(2) a labelled host corpus**, then **(3)** adopt
**Bernoulli Naive Bayes** behind the `Classifier` trait (it also yields calibrated
probabilities, subsuming E5's softmax and E3's hand weights). For *discovering*
new profiles, use a density clusterer (HDBSCAN / k-modes) over host vectors
rather than k-means.
