## Reading this

- **`--ml` reaches paths stock cannot.** The ML-only finds are the `/api/v1` and `/api/v2` subtrees and `/users/me` — nested resources whose path tokens (`v1`, `v2`, `me`) are not in the wordlist. The layer fingerprints the target as `REST_API` and injects those tokens as per-directory predictions.
- **It costs more requests.** `--ml` injects extra guesses per directory, so request count rises. A comparable `found/req` means those extra requests are about as productive as the base wordlist — they buy reach, not noise.
- **Synthetic target.** `bench/structured_server.py` is a controlled illustration of the *mechanism*, not a yield claim about real targets. Run against your own authorized target to measure real-world lift.
- **Stability.** The local Python server drops requests under high concurrency; use a low `-t` (e.g. `-t 10`) for repeatable counts. Deep-tree finds (e.g. `/api/v1/users/me`) can vary run to run as online learning order shifts.
